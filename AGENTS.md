# Agent Instructions

These rules apply to every AI coding agent working in this repository (Claude Code, Codex, GitHub Copilot, ...).
Human-oriented setup details are in [BUILDING.md](BUILDING.md).

## Environment

- The project uses [Pixi](https://pixi.sh/) (Windows, Python 3.11). Run everything through it; do not use `pip install`.
  - Tests: `pixi run test`, or `pixi run pytest tests/test_x.py -k name`
  - Any Python: `pixi run python ...`
  - Dependencies: `pixi add <pkg>` (conda-forge) or `pixi add --pypi <pkg>`; commit `pyproject.toml` and `pixi.lock` together.
- `pyemsi/core/femap_parser` is a Cython extension. Edit the `.pyx`; the generated C in `build/` is not tracked.
  Rebuild with `pixi run python setup.py build_ext --inplace`.

## Formatting (Ruff only)

The goal is zero formatting churn: every line in a diff should be there because its code changed.

- Format with `pixi run format` (Ruff, pinned in `pixi.lock`; settings in `[tool.ruff]` of `pyproject.toml`).
  **Never** run Black, isort, autopep8, yapf, or Ruff with command-line overrides such as `--line-length`.
- Line length is **120**, not Black's default of 88. Write code at that width:
  - Keep a call, signature, or literal on one line if it fits in 120 columns.
  - Don't add a trailing comma to a construct that fits on one line. Ruff treats a trailing comma as
    "keep this exploded", so an 88-column style would stay permanently.
- Double quotes, LF line endings (enforced by `.gitattributes`).
- Only format files you changed; don't reformat unrelated code.
- Don't edit or format the excluded files:
  - `pyemsi/resources/resources.py` is generated by `pyside6-rcc` (see BUILDING.md).
  - Python snippets inside Markdown files are not formatted.

## Imports

- **Never sort or reorder imports**, and don't enable Ruff's `I` (isort) rules.
  FreeCAD modules are import-order sensitive, and reordering can break them at runtime.
- Add new imports next to related ones without reshuffling the existing lines.
- An import that looks unused may exist for its side effects (FreeCAD, Qt, VTK). Don't delete it just because a linter flags it.
  If it's intentional, mark it with a reason: `# noqa: F401 - registers ...`.

## Linting

- `pixi run lint` must pass. The rule set (`E4`, `E7`, `E9`, `F`) is intentionally minimal; don't expand it.
- Don't run `ruff check --fix` or `--unsafe-fixes` across the codebase. Fix findings by hand in the files you touched.
- Use `# noqa: <code> - <reason>` only for deliberate cases, e.g. imports that must come after setup code (`E402`).

## Git

- Install hooks once per clone: `pixi run install-hooks`. The pre-commit hook runs `ruff format` and `ruff check`
  on staged Python files.
- If the hook reformats files, review the change, `git add` again, and commit. **Never bypass it** with `--no-verify`.
- Keep formatting-only changes out of feature commits. If a formatting-only commit is unavoidable, make it separately
  and add its hash to `.git-blame-ignore-revs`.
