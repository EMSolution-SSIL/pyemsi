# One Branch, Two Installers Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** pyemsi and the FreeCAD add-on live on one branch and one release builds two installers: pyemsi without FreeCAD, and EMSolution-FreeCAD with FreeCAD + add-on + pyemsi.

**Architecture:** The FreeCAD tabs leave the pyemsi package (kept on `experimental/freecad-viewer`); FreeCAD and the add-on's dependency move into a separate pixi environment; both installers read one version from `pyemsi.__version__`; a checker refuses any pyemsi output that contains FreeCAD, the add-on or `ems_material`.

**Tech Stack:** pixi (features/environments), setuptools, NSIS, rattler-build + constructor, GitHub Actions, pytest.

**Spec:** `docs/superpowers/specs/2026-10-22-two-installers-one-branch-design.md`

## Global Constraints

- Work on `feature/freecad-addon`. Create `experimental/freecad-viewer` locally only. **No push, no merge into `main`, no tag, no release** — those wait for the user.
- pixi only (`pixi run ...`, `pixi add`); commit `pyproject.toml` and `pixi.lock` together. Ruff, line length 120; never reorder imports; `pixi run format` reformats the unrelated `highlight.py` — revert it.
- `pyemsi/resources/resources.py` is generated by `pyside6-rcc` (see BUILDING.md); regenerate it, never hand-edit it.
- One version: `pyemsi.__version__` (in `pyemsi/__init__.py`) is the only place a version number is written; the add-on, both installers and all recipes take it from there.
- pyemsi outputs (wheel, sdist, portable runtime, NSIS installer) contain no `freecad_addon`, no `FreeCAD`/`FreeCADGui` import, no `ems_material`.
- Forbidden names for the checker, exactly: `freecad_addon`, `FreeCAD`, `FreeCADGui`, `ems_material`, `ems-material-manager`.
- Python stays 3.11 in both environments.
- Commit messages end with your environment's Co-Authored-By line. Never `--no-verify`.

## Decisions this plan adds to the spec

1. **Explorer and `.FCStd` (spec open point):** after the tabs are removed, an `.FCStd` file is treated like any other file pyemsi has no viewer for — same code path, no special case, no FreeCAD icon. The FreeCAD icon resource is removed and `resources.py` regenerated.
2. **Generic pieces stay.** Code that is not FreeCAD-only stays, renamed where its name says FreeCAD: e.g. the terminal dock's `add_log_tab` (tests use "FreeCAD messages" only as a label — change the label), and any graphics/OpenGL launch policy that VTK or WebEngine also needs. Only FreeCAD-only code is removed.
3. **One version script:** `installer/version.py` prints `pyemsi.__version__` (parsed from `pyemsi/__init__.py` without importing pyemsi); tasks and CI use it.
4. **Local NSIS:** `installer-pyemsi` uses `makensis` from the `installer/freecad` pixi workspace (it already has `nsis`), so no system NSIS is needed locally; CI keeps its current NSIS step.
5. **The add-on's PyPI dependency in the FreeCAD installer** gets a rattler-build recipe like the existing `ems-file-format-converter` one (repackaged wheel), and the add-on recipe depends on it.

## Review Focus

1. A user whose saved pyemsi settings/session still lists a FreeCAD tab or split from 0.6.0: pyemsi starts and ignores it (Task 1 test).
2. pyemsi GUI starts and opens files in an environment without FreeCAD (Task 1: the GUI launch tests run in the default environment after Task 2).
3. CI runs the add-on tests too, not only the default-environment tests (Task 2: `tests.yml` runs both).
4. A version bump in `pyemsi/__init__.py` reaches both installers' file names and metadata with no other edit (Task 3 test: no literal versions in recipes/construct.yaml).
5. A pyemsi dependency later pulling `ems_material` or FreeCAD into the portable runtime: the CI check fails (Task 4: checker runs on the portable runtime directory too).
